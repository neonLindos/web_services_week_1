# Практическая работа со преподавателем — Модуль 01

**Тема:** Введение в ASP.NET Core, первая конечная точка в API
**Проект:** `CoursesApi` (Course)

## Используемые технологии

Visual Studio 2022+, C#, ASP.NET Core Web API, .NET 8 (LTS), Swagger/OpenAPI. База данных не используется — данные хранятся в памяти приложения (статический список).

## Как запустить

```bash
cd lab
dotnet run
```

Откройте Swagger UI по адресу из вывода консоли.

## Что реализовано

Постановка задачи требовала полный набор операций (получить все / по Id / добавить / изменить / удалить), поэтому помимо двух заданий из методички (GetAll, GetById) добавлены Create/Update/Delete:

| Метод | Endpoint | Назначение | Успешный код | Код ошибки |
|---|---|---|---|---|
| GET | `/api/courses` | получить список всех курсов | 200 OK | — |
| GET | `/api/courses/{id}` | получить курс по Id | 200 OK | 404 Not Found |
| POST | `/api/courses` | добавить новый курс | 201 Created | — |
| PUT | `/api/courses/{id}` | изменить существующий курс | 204 No Content | 404 Not Found |
| DELETE | `/api/courses/{id}` | удалить курс | 204 No Content | 404 Not Found |

## Ответ на вопрос из методички

**Почему Web API должен возвращать 404, а не просто пустой объект?**

Потому что пустой объект (или `null`) не различает две разные ситуации: "ресурс не существует" и "ресурс существует, но его поля пусты". HTTP-код — часть стандартного протокола, на который ориентируются и клиентский код, и промежуточное ПО (кэши, логирование, мониторинг, автотесты): по коду 404 клиент однозначно понимает, что искать/показывать нечего, не разбирая содержимое тела ответа. Это также соответствует принципам REST — семантика ответа должна передаваться статус-кодом, а не самим содержимым данных.

## Контрольные вопросы

1. **Что такое Web API?** — программный интерфейс для обмена данными между приложениями по HTTP, обычно в формате JSON, без графического интерфейса.
2. **Чем Web API отличается от обычной веб-страницы?** — обычная страница возвращает готовый HTML для отображения человеку в браузере; Web API возвращает структурированные данные для обработки программой или другим сервисом.
3. **Что такое клиент-серверная архитектура?** — модель, в которой клиент инициирует запросы, а сервер их обрабатывает и возвращает результат; роли чётко разделены, связь идёт по сети через протокол (например, HTTP).
4. **Что такое HTTP request?** — сообщение от клиента серверу: метод, URL, заголовки, тело.
5. **Что такое HTTP response?** — ответ сервера клиенту: код статуса, заголовки, тело с результатом.
6. **Что такое endpoint?** — конкретный адрес API (URL + HTTP-метод) для выполнения операции.
7. **Для чего используется HTTP GET?** — получение данных без изменения состояния сервера.
8. **Для чего используется POST?** — создание нового ресурса.
9. **В чём отличие PUT от POST?** — PUT используется для полного обновления/замены уже существующего ресурса по известному Id и идемпотентен (повторный вызов с теми же данными не меняет результат); POST создаёт новый ресурс и не идемпотентен — каждый вызов может породить новый объект.
10. **Для чего используется DELETE?** — для удаления ресурса по его идентификатору.
11. **Что означает HTTP Status Code 200?** — успешный запрос, есть тело с результатом (обычно GET).
12. **Что означает 201?** — ресурс успешно создан (обычно ответ на POST), часто с заголовком `Location`, указывающим на новый ресурс.
13. **Что означает 204?** — запрос выполнен успешно, но тело ответа отсутствует (типично для PUT/DELETE).
14. **Что означает 404?** — запрошенный ресурс не найден.
15. **Что такое JSON?** — текстовый формат обмена данными в виде пар "ключ-значение" и массивов.
16. **Что делает атрибут [HttpGet]?** — помечает метод контроллера как обработчик HTTP GET-запросов к указанному маршруту.
17. **Для чего используется [Route]?** — задаёт шаблон URL-маршрута для контроллера или отдельного метода.
18. **Что делает ControllerBase?** — базовый класс для Web API-контроллеров (без Views); предоставляет методы вроде `Ok()`, `NotFound()`, `CreatedAtAction()`, `NoContent()` для формирования HTTP-ответов.
19. **Что такое Swagger?** — инструмент для автогенерации документации API и интерактивного тестирования endpoint'ов через браузер.
20. **Почему Web API удобно использовать для взаимодействия нескольких информационных систем?** — он предоставляет унифицированный, независимый от языка и платформы интерфейс обмена данными по HTTP в стандартном формате (JSON), что позволяет системам на разных технологиях легко взаимодействовать друг с другом, не зная деталей внутренней реализации.
