# Лабораторная работа — Модуль 01 (вариант на Node.js)

**Тема:** Разработка простого Web-сервиса с использованием REST API
**Проект:** `web-service-lab` (Student)
**Используемые технологии:** Node.js, Express.js, HTML5, CSS3, JavaScript (fetch), JSON, REST API, HTTP.

> Это вторая версия лабораторной. Первая методичка была по ASP.NET Core (курс `Course`) — её решение в папке [`../lab`](../lab). Выданная позже методичка `лабораторная работа 1.docx` требует Node.js + Express и ресурс «студенты», поэтому решение вынесено сюда, в `lab_js`.

## Как запустить

1. Установить [Node.js](https://nodejs.org) (LTS).
2. Скопировать содержимое этой папки (`server.js`, `package.json`, `public/`) в каталог проекта.
3. В терминале в каталоге проекта выполнить `npm install` (поставит Express).
4. Запустить сервер: `npm start` (или `node server.js`).
5. Открыть в браузере `http://localhost:3000` — откроется Web-интерфейс со списком студентов; API доступно по адресу `http://localhost:3000/api/students`.

## Что реализовано

Данные хранятся в памяти приложения (массив `students` с двумя заготовленными записями). Реализован полный набор операций из задания:

| Метод | Endpoint | Назначение | Успешный код | Код ошибки |
|---|---|---|---|---|
| GET | `/api/students` | получить список всех студентов | 200 OK | — |
| GET | `/api/students/:id` | получить студента по id | 200 OK | 404 Not Found |
| POST | `/api/students` | добавить нового студента (id генерируется) | 201 Created | 400 Bad Request (нет `name` или `group`) |
| PUT | `/api/students/:id` | изменить данные студента | 200 OK | 404 Not Found |
| DELETE | `/api/students/:id` | удалить студента | 200 OK | 404 Not Found |

Модель студента:

```json
{
  "id": 1,
  "name": "Иван Иванов",
  "group": "ИС-21"
}
```

Плюс Web-интерфейс (`public/index.html` + `public/style.css` + `public/script.js`): форма добавления студента, список карточек с кнопкой «Удалить», все обращения к серверу — через `fetch` без перезагрузки страницы. Статику отдаёт сам Express (`express.static("public")`).

## Отличия от версии на ASP.NET Core (`../lab`)

| | `../lab` (ASP.NET Core) | `lab_js` (Node.js) |
|---|---|---|
| Ресурс | курсы (`Course`) | студенты (`Student`) |
| Сервер | Kestrel + контроллеры `[ApiController]` | Express, маршруты `app.get/post/put/delete` |
| Хранение | `static List<Course>` в контроллере | массив `students` в `server.js` |
| Проверка API | Swagger UI | Web-страница `public/index.html` + Postman/curl |
| Код POST | `201 Created` + `CreatedAtAction` | `201 Created` + тело нового объекта |
| Код PUT/DELETE | `204 No Content` | `200 OK` + изменённый / удалённый объект (как в методичке) |

## Контрольные вопросы

*(методичка `лабораторная работа 1.docx` отдельного списка вопросов не содержит; ниже — базовые вопросы по теме REST API, общие с версией `../lab`)*

1. **Что такое REST?** — архитектурный стиль взаимодействия по HTTP, где каждая сущность представлена ресурсом с собственным URL, а операции над ним выражаются стандартными HTTP-методами.
2. **Что такое endpoint?** — конкретная пара «URL + HTTP-метод», обрабатывающая одну операцию API (например, `GET /api/students/:id`).
3. **Для чего используются GET, POST, PUT, DELETE?** — GET читает данные, POST создаёт новый ресурс, PUT изменяет существующий, DELETE удаляет.
4. **Что делает `express.json()`?** — это middleware, разбирающий тело запроса с `Content-Type: application/json` и складывающий результат в `req.body`.
5. **Что делает `express.static("public")`?** — отдаёт файлы из папки `public` как есть (HTML, CSS, JS), благодаря чему по адресу `/` открывается `index.html`.
6. **Зачем при отсутствии студента возвращать 404, а не пустой объект?** — код статуса — часть протокола: по 404 клиент и промежуточное ПО (кэш, логи, тесты) сразу понимают, что ресурса нет, не разбирая тело ответа.
7. **Что означает код 201?** — ресурс успешно создан (ответ на POST); в теле возвращается созданный объект с присвоенным `id`.
8. **Что означает код 400?** — некорректный запрос; здесь — не переданы обязательные поля `name` или `group`.
9. **Почему id генерируется на сервере, а не приходит от клиента?** — сервер — единственный владелец данных и гарантирует уникальность id; клиент не знает текущего состояния списка.
10. **Что такое JSON?** — текстовый формат обмена данными в виде пар «ключ-значение» и массивов, независимый от языка программирования.
11. **Почему запросы с фронтенда идут через `fetch`, а не через отправку формы?** — `fetch` позволяет обменяться с API JSON-ом и обновить только список на странице, без полной перезагрузки.
12. **Чем Web-сервис удобен для взаимодействия нескольких систем?** — он даёт единый, независимый от платформы интерфейс обмена данными по HTTP в формате JSON, скрывая детали внутренней реализации.
