# Практическая работа — Модуль 01

**Тема:** Разработка простого веб-сервера на Node.js с обработкой HTTP-запросов, маршрутизацией и подключением к базе данных
**Проект:** `web-server` (User)
**Используемые технологии:** Node.js, Express.js, SQLite3, JSON, REST API, HTTP.

## Как запустить

1. Установить [Node.js](https://nodejs.org) (LTS).
2. Скопировать содержимое этой папки (`server.js`, `package.json`) в каталог проекта `web-server`.
3. В терминале в каталоге проекта выполнить `npm install` (поставит Express и sqlite3).
4. Запустить сервер: `npm start` (или `node server.js`).
5. В консоли появится `Сервер запущен: http://localhost:3000`; проверить маршруты в браузере или через Postman/curl. При первом запуске в папке проекта создаётся файл базы данных `database.db` с таблицей `users` и двумя заготовленными записями.

## Что реализовано

Данные хранятся в SQLite (`database.db`, таблица `users`, создаётся автоматически при первом запуске командой `CREATE TABLE IF NOT EXISTS`). Реализованы все маршруты из задания:

| Метод | Endpoint | Назначение | Успешный код | Код ошибки |
|---|---|---|---|---|
| GET | `/` | проверка работы сервера | 200 OK | — |
| GET | `/users` | получить список пользователей из базы данных | 200 OK | 500 Internal Server Error (ошибка БД) |
| POST | `/users` | добавить нового пользователя | 201 Created | 400 Bad Request (нет `name` или `email`) |

Модель пользователя:

```json
{
  "id": 1,
  "name": "Иван Иванов",
  "email": "ivan@example.com"
}
```

При первом запуске таблица `users` заполняется двумя записями (Иван Иванов, Петр Петров), если она пуста — проверка через `SELECT COUNT(*)`. Все запросы к базе — через параметризованные `?`-плейсхолдеры (`db.run`/`db.get`/`db.all`), что защищает от SQL-инъекций.

## Контрольные вопросы

1. **Чем `sqlite3` отличается от хранения данных в массиве в памяти?** — SQLite пишет данные в файл на диске (`database.db`), поэтому они переживают перезапуск сервера, в отличие от массива, который создаётся заново при каждом старте.
2. **Зачем нужен `CREATE TABLE IF NOT EXISTS`?** — чтобы таблица создавалась только один раз при первом запуске и повторные запуски сервера не приводили к ошибке «таблица уже существует».
3. **Почему код инициализации обёрнут в `db.serialize()`?** — драйвер `sqlite3` асинхронный и может выполнять запросы параллельно; `serialize` гарантирует, что `CREATE TABLE` выполнится раньше проверки и вставки начальных данных.
4. **Чем `db.get`, `db.all` и `db.run` отличаются друг от друга?** — `db.get` возвращает одну строку результата, `db.all` — все строки, `db.run` выполняет запрос без возврата строк (INSERT/UPDATE/DELETE/CREATE) и даёт доступ к `this.lastID`/`this.changes`.
5. **Зачем в запросах использовать `?` вместо подстановки значений в строку напрямую?** — параметризованные запросы защищают от SQL-инъекций и корректно экранируют пользовательский ввод.
6. **Откуда берётся `id` нового пользователя?** — SQLite сам генерирует его через `INTEGER PRIMARY KEY AUTOINCREMENT`, значение доступно после вставки как `this.lastID`.
7. **Почему при ошибке базы данных возвращается 500, а не 200 с пустым телом?** — 500 явно сообщает клиенту, что запрос не выполнен из-за проблемы на сервере, а не что данных просто нет.
8. **Что делает `express.json()`?** — middleware, разбирающий тело запроса с `Content-Type: application/json` в объект `req.body`.
9. **Почему проверка `!name || !email` выполняется до обращения к базе?** — чтобы не отправлять в БД заведомо некорректный запрос и сразу вернуть клиенту 400 с понятным сообщением.
